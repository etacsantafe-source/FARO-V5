## B3 — Investigación externa y alternativas
- **Tasks.org** (software real) docs https://tasks.org/docs/backups/ y changelog https://github.com/tasks/tasks/blob/main/CHANGELOG.md (v15.7.1, fix duplicación de tareas al importar backup y fallos con backups viejos): **ADAPTAR** pruebas de reversibilidad y no-duplicación; no incorporar code/dependencia, sin dependencia nube.
- **Joplin backup plugin** https://github.com/JackGruber/joplin-plugin-backup/blob/master/FULLRESTORE.md : advierte que un restore puede duplicar elementos y cambiar IDs; **ADAPTAR** idempotencia/ID estable, **DESCARTAR** importación duplicativa con nuevas identidades.
- **Joplin E2EE** https://joplinapp.org/help/dev/spec/e2ee/ documenta header versionado y chunks para datos grandes: **REFERENCIA** de contenedor versionado y límites; código propio Kotlin sin dependencia ni copia.
- **SQLite oficial** https://www.sqlite.org/lang_transaction.html confirma BEGIN IMMEDIATE, rollback y no anidamiento: **REFERENCIA** para futuro restore, en este bloque solo codec en memoria. **OWASP MASVS-STORAGE** https://mas.owasp.org/MASVS/05-MASVS-STORAGE/ evita leaks en backups: **USAR** no loguear secretos/títulos ni crear exportaciones sin AEAD y consentimiento. Licencia de terceros irrelevante porque no se copia su código y no se agrega dependencia.
- Test adversarial inspirado: v2 con sección maliciosa, Unicode inválido, tamaño/orden incoherente y sección inventada, faltante o adulterada es rechazado ANTES de que un futuro restaurador lea un owner.
