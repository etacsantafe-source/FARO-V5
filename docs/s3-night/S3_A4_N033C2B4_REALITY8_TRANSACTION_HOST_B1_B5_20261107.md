## B3 — Investigación y decisión
- SQLite oficial https://sqlite.org/lang_transaction.html : `BEGIN IMMEDIATE` y COMMIT/ROLLBACK en un mismo archivo protegen fila owner+receipt, no dos bases; ADAPTAR RealityStore actual.
- Android Processes https://developer.android.com/guide/components/processes-and-threads : por defecto componentes de la app comparten proceso, pero `android:process` puede crear otros. LIMITAR alcance a host Android local de una instalación; NO certificar cross-process sin manifest merged y pruebas.
- OWASP Authorization https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html : deny by default y verificar operación/objeto; usar `ApplyTransactionAuthorizationPort` en cada nodo y de nuevo antes de receipt, con scope exacto y transactionId.
- OWASP Authorization Patterns https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Patterns_Cheat_Sheet.html : enforcement próximo al recurso, NO policy allow-all.
- Java synchronized JLS 17 https://docs.oracle.com/javase/specs/jls/se21/html/jls-17.html : monitor del owner retiene lock hasta que termina callback; `owner.close` por otra hebra espera, callback host no suspende/hace dispatch de otro thread.
- DESCARTAR `owner.epochOrNull` dentro Reality mutex (lee Workspace por policy), callbacks post-commit de autorización (podrían mentir sobre un efecto), revalidar mediante UI o LLM, y subir 8 schemas a todos los owners.
