## B3 — Investigación externa, alternativas reales y selección
Fuentes primarias con semántica verificable; no copiar código externo:
- Android official app architecture https://developer.android.com/topic/architecture : single source of truth, eventos UI→owner y estado propietario. **ADAPTAR** puente explícito hacia N-018; DESCARTAR mutación directa desde una vista.
- Android offline-first https://developer.android.com/topic/architecture/data-layer/offline-first : lecturas locales + persistencia con intención de usuario; **REFERENCIA** para transacciones sin nube/servicio extra, no justifica inferir permiso.
- Android lifecycle/coroutines https://developer.android.com/topic/libraries/architecture/coroutines : cancelar al salir de pantalla, pero lifecycle solo no garantiza ACL. **ADAPTAR** revocación y fence final, DESCARTAR consentimiento por reanudación.
- SQLite atomic commit https://www.sqlite.org/atomiccommit.html y isolation https://www.sqlite.org/isolation.html : alcance del COMMIT y transacciones, pero snapshot SQL no prueba permiso de otro owner. **USAR** transacción ya existente y **ADAPTAR** revalidación Workspace antes/después. SQLite es public domain, sin nueva dependencia.
- Slack saved items https://slack.com/help/articles/360042650274-Save-messages-and-files-for-later : **REFERENCIA UX** de guardado mediante intención explícita; DESCARTAR cloud y equivalencia de sus ACL internas.
- Chromium BookmarkModelObserver https://chromium.googlesource.com/chromium/src/+/refs/tags/138.0.7204.61/components/bookmarks/browser/bookmark_model_observer.h : **REFERENCIA** lifecycle/invalidation; no asumir que callback significa consentimiento o garantía durable; proyecto con licencia BSD-style, ninguna dependencia propuesta.

## B5 — Auditoría adversarial previa y condiciones STOP
- P1: un permiso de **lectura** no puede escribir ni reutilizar un receipt (el puerto de lectura debe seguir sin `mutate`).
- P2: no hay grant al construir host; foreground/UID/manifest no son prueba de gesto humano. En esta unidad NO se emite ese gesto desde pantalla, solo se modela su futura admisión.
- P3: target con mismo messageId en otra conversación, texto oculto/borrado/archivado, ACL revocada, generación diferente o ABA: `Unavailable` sin metadatos ni receipt nuevo.
- P4: token Workspace/revision cambia entre preflight, transacción y resultado → rollback cuando sea previo a commit; si efecto ya committed, repetir idempotency key y consultar receipt tras nueva autorización, nunca duplicar ni afirmar rollback post-commit.
- P5: mismo idempotencyKey con payload diferente → `IdentityConflict`; repetición idéntica y autorizada → mismo receipt `replayed=true`; revision stale → `Stale` y cero side effects.
- P6: clausura de Auxiliary/Workspace, onPause, cierre de host o crash → no publicar un éxito capturado sin check final. Se debe explicar resultado `UNKNOWN/RECONCILE` tras crash post-COMMIT, no falsificar `Reality COMMITTED`.
- P7: no superar cuota 1024 bookmarks/32 carpetas, eliminación de carpeta no vacía NO cascada, mover al root requiere acción explícita; no modificar semántica actual.
- P8: test de race para lock/gate (sin deadlock: no tomar locks host desde callbacks dentro del owner); sin conectores remotos, pagos, red, background writes, datos de usuario, nuevos permisos ni V2 productiva.
- **STOP** si el ejecutor no puede demostrar un gesto confiable y la distinción entre grant de lectura/mutación; si nueva clase necesita tocar otro archivo no permitido, emitir `STALE_NEEDS_DELTA_REAUDIT` en vez de parche fuera del permiso. CI de prueba siempre sobre SHA real; runner running ≠ PASS.

Salida: `PREAUDITED` hasta permiso documental preciso y guard preflight. Primer B6 no debe montar mutación de UI ni declarar cierre de A3. Dependencias siguientes: Chat→Review explícito y navegación exacta al mensaje (paquetes separados), aceptación integrada A3/A5 y G15 campaña final.
