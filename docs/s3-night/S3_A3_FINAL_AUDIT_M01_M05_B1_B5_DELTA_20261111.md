- Android arquitectura https://developer.android.com/topic/architecture/recommendations : fuerte separación UI/datos y single source of truth. ADAPTAR: host solo acepta intent y delega DB al owner; DESCARTAR UI Compose→SQLite.
- Android navegación https://developer.android.com/guide/navigation/use-graph/pass-data : pasar referencia mínima, no objeto/texto/token. ADAPTAR M04; no declarar que Navigation3 se comporta igual que Navigation2 (principio SSOT, no API reutilizada literalmente).
- SQLite https://www.sqlite.org/lang_transaction.html : BEGIN IMMEDIATE serializa escritores, pero no valida ACL externa. USAR misma conexión, lock, receipt; nunca asumir SQLite COMMIT certifica fuente Workspace.
- SQLite https://www.sqlite.org/isolation.html : transacciones de conexiones separadas no proporcionan atomicidad cruzada entre dos owners. ADAPTAR pre/post Workspace fences y fail-closed para revocaciones; no prometer multi-DB atomic transaction.
- GitHub https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax : workflow_dispatch solo recibe eventos si archivo está en default branch; no tocar main. USAR on:push branch work/s3-night-20261102 con paths exactos y SHA; workflow_dispatch existente si funciona, no depender de uno nuevo.
- Slack https://slack.com/help/articles/360042650274-Save-messages-and-files-for-later : referencia de gesto humano por mensaje; DESCARTAR nube/cuenta externa.
Sin nueva API paga, servicio, biblioteca ni licencia nueva. Alternativas rechazadas: grant genérico compartido, per-request mutable global, lookup de REMOVED abierto a toda UI, otra base SQLite, falso Reality COMMITTED, manual workflow_dispatch sobre archivo solo de rama.
