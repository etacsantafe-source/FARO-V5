## Convenciones de certeza y aceptación
**IMPLEMENTADO**: existe código real de esa responsabilidad y al menos evidencia concreta de ejecución/invariante; puede ser solo alcance interno o test. **PARCIAL**: hay código pero falta conexión a host, interfaz, datos o certificación para el flujo completo. **SOLO_CONTRATO**: contrato / descriptor / interfaz / destino UI sin ejecución real demostrada. **AUSENTE**: ausencia de la capacidad específica en el host/recorrido inspeccionado; no es afirmación de inexistencia universal en cada archivo del repo. Cuando no se verificó un eje se marca **NO_VERIFICADO**, no AUSENTE.

Desglosar por ejes **C** contrato, **I** implementación interna, **H** host/montaje, **U** UI/gesto, **T** prueba. Tener `build.gradle.kts`, OperationContract `BINDABLE`, test unitario, un botón o un destino enum **no** equivale a función de producto terminada. Emulador != Moto G15; debug != productiva; recibo simulado != Reality COMMITTED.

## Verificaciones transversales / distinciones que no se pueden colapsar
1. **Contratos ≠ implementación**: 180 operaciones en `v5/spec/generated/contract-baseline.tsv` (conteo directo de prefijo `operation\t`); el inventario registra además cuatro superficies/domain owners útiles pero no 180 acciones listas.
2. **SQLite ≠ UI**: RealityStore real ofrece `financePersistence.createAccount/recordEntry`, `objectivePersistence.upsert`, `matterPersistence.upsert` en el transaction scope; CORE DEV no expone al usuario editores de esos registros. Los cuatro resultados de X06 se sembraron **en test** `v5/app/src/g5AndroidTest/.../FaroV5S3A57X06FourOwnerSearchUiTest.kt`, blob `f62b28addb46bfdab53577491554ccc56515cf4e`.
3. **Reality8 ≠ migración 7→8**: `RealityStore.kt` constructor `planningStage8=false` y APIs staged-only; botón «Crear Reality8 vacía (DEV)» explica que no copia datos de Reality7. Nunca deducir cutover automático ni recuperación física.
4. **Search/Activity/Avisos ≠ dueño o permiso global**: snapshots tipados y reads grant-explicit, invalidación por owner/foreground; si el puerto está ausente o cae, debe ser UNAVAILABLE/PARTIAL, no «cero».
5. **APPLY canónico ≠ modelo real**: la suite offline test usa un candidato Profile de fixture con recibo **Reality COMMITTED** genuino en una raíz debug; no genera IA remota ni disponibilidad de Groq gratuita, ni sella Apply multiowner genérico.
6. **Archivo o nombre histórico desactualizado**: `docs/v5/V5_OPERATION_CONTRACT_INVENTORY.md` conserva referencias a subtotales 172 en secciones viejas; apéndice aprobado del 10/11, catálogo TSV y pointer vigente resuelven a **180**. `README.md` declara PRIVATE; gobernanza y metadata actuales PUBLIC. No corregirlos dentro de P01 documental para no ampliar scope.
7. **Cinco propietarios de generación ≠ seis módulos owner de dominio**: contar recursos reales, no inferir por nombres Gradle.
8. **P00 aprobado ≠ P01 implementado**: landing Chat, drawer V4.4, Radar integrado y 6 meses son requisitos; los flujos finales se estudiarán por P02–P07, no se reescriben durante inventario.
